OPIS PROJEKTU VERITY - DO WYGENEROWANIA DIAGRAMU UML

================================================================================
NAZWA PROJEKTU: Verity - Zdecentralizowany System Głosowania
================================================================================

OGÓLNY OPIS:
Verity to system głosowania oparty na blockchain Ethereum, składający się z trzech głównych warstw: smart kontraktu (Solidity), backendu (Rust) i aplikacji mobilnej (Swift - w fazie projektowania). System umożliwia transparentne i niezmienne głosowanie poprzez blockchain, z backendem optymalizującym dostęp do danych.

================================================================================
ARCHITEKTURA SYSTEMU
================================================================================

WARSTWA 1: BLOCKCHAIN (Smart Contract - Solidity)
--------------------------------------------------

Kontrakt: VotingSystem

Struktury danych:
- Proposal
  * id: uint256
  * title: string
  * description: string
  * creator: address
  * options: string[] (tablica opcji do głosowania)
  * votesCount: uint256[] (liczniki głosów dla każdej opcji)
  * deadline: uint256 (timestamp zakończenia głosowania)
  * isActive: bool
  * createdAt: uint256

- Vote (nie jest przechowywana jako struct, ale reprezentowana przez mappingi)
  * voter: address
  * proposalId: uint256
  * optionIndex: uint256
  * timestamp: uint256

Główne funkcje (publiczne):
- createProposal(title: string, description: string, options: string[], durationDays: uint256) → returns proposalId: uint256
- vote(proposalId: uint256, optionIndex: uint256)
- endProposal(proposalId: uint256)
- getProposal(proposalId: uint256) → returns Proposal
- getProposalOptions(proposalId: uint256) → returns string[]
- getProposalVotesCount(proposalId: uint256) → returns uint256[]
- getTotalVotes(proposalId: uint256) → returns uint256
- getWinningOption(proposalId: uint256) → returns (winningOption: uint256, winningVoteCount: uint256)
- hasUserVoted(proposalId: uint256, voter: address) → returns bool
- isProposalActive(proposalId: uint256) → returns bool

Zmienne stanu:
- proposalCount: uint256
- proposals: mapping(uint256 => Proposal)
- hasVoted: mapping(uint256 => mapping(address => bool))
- userVote: mapping(uint256 => mapping(address => uint256))

Wydarzenia (Events):
- ProposalCreated(proposalId, creator, title, deadline, optionsCount)
- VoteCast(proposalId, voter, optionIndex, timestamp)
- ProposalEnded(proposalId, timestamp)

Stałe:
- MIN_VOTING_DURATION = 1 day
- MAX_VOTING_DURATION = 90 days
- MIN_OPTIONS = 2
- MAX_OPTIONS = 10

================================================================================
WARSTWA 2: BACKEND (Rust + Axum)
================================================================================

MODUŁ: BlockchainClient
-----------------------
Odpowiedzialność: Komunikacja z blockchainem Ethereum przez Alloy-rs

Atrybuty:
- provider: RootProvider<Http<Client>>
- contract_address: Address

Metody:
- new(config: &BlockchainConfig) → Result<Self>
- get_block_number() → Result<u64>
- get_proposal_count() → Result<U256>
- get_proposal(proposal_id: U256) → Result<VotingSystem::Proposal>
- get_proposal_options(proposal_id: U256) → Result<Vec<String>>
- get_proposal_votes_count(proposal_id: U256) → Result<Vec<U256>>
- get_total_votes(proposal_id: U256) → Result<U256>
- is_proposal_active(proposal_id: U256) → Result<bool>
- has_user_voted(proposal_id: U256, voter: Address) → Result<bool>
- get_winning_option(proposal_id: U256) → Result<(U256, U256)>

MODUŁ: Database (SurrealDB)
----------------------------
Odpowiedzialność: Przechowywanie i indeksowanie danych z blockchain

Atrybuty:
- client: Surreal<Client>

Metody:
- new(config: &DatabaseConfig) → Result<Self>
- create_proposal(proposal: &Proposal) → Result<Proposal>
- get_proposal(proposal_id: u64) → Result<Option<Proposal>>
- get_all_proposals() → Result<Vec<Proposal>>
- update_proposal(proposal: &Proposal) → Result<Proposal>
- create_vote(vote: &Vote) → Result<Vote>
- get_votes_for_proposal(proposal_id: u64) → Result<Vec<Vote>>
- has_voted(proposal_id: u64, voter: &str) → Result<bool>

MODUŁ: Indexer
--------------
Odpowiedzialność: Nasłuchiwanie i indeksowanie wydarzeń z blockchain

Atrybuty:
- blockchain: BlockchainClient
- database: Database
- poll_interval: Duration

Metody:
- new(blockchain: BlockchainClient, database: Database) → Self
- start() → Result<()>
- index_new_events() → Result<()>
- process_proposal_created(event) → Result<()>
- process_vote_cast(event) → Result<()>

MODUŁ: API (REST Endpoints)
----------------------------
Odpowiedzialność: Udostępnianie danych przez REST API

Endpoints (Handlers):
- GET /health → health_check()
- GET /api/blockchain → get_blockchain_info()
- GET /api/proposals → get_proposals()
- GET /api/proposals/:id → get_proposal(id)
- GET /api/proposals/:id/votes → get_proposal_votes(id)
- GET /api/proposals/:id/results → get_proposal_results(id)

AppState (współdzielony stan):
- db: Database
- blockchain: BlockchainClient

================================================================================
PRZEPŁYW DANYCH
================================================================================

TWORZENIE PROPOZYCJI:
User → App → Transaction (signed) → Blockchain → VotingSystem.createProposal()
→ emit ProposalCreated → Indexer → Database → API → App (refresh)

GŁOSOWANIE:
User → App → Transaction (signed) → Blockchain → VotingSystem.vote()
→ emit VoteCast → Indexer → Database → API → App (refresh)

ODCZYT DANYCH:
User → App → Backend API → Database (cache) → Response
                  ↓ (jeśli brak w cache)
            BlockchainClient → Ethereum RPC → Smart Contract → Response

================================================================================
RELACJE MIĘDZY KOMPONENTAMI
================================================================================

1. Smart Contract VotingSystem (Blockchain)
   - emituje wydarzenia: ProposalCreated, VoteCast, ProposalEnded
   - przechowuje: Proposals, Votes (jako mappingi)

2. BlockchainClient (Backend)
   - komunikuje się z: Smart Contract
   - używany przez: Indexer, API Handlers

3. Database (Backend)
   - przechowuje zaindeksowane: Proposals, Votes
   - używana przez: Indexer, API Handlers

4. Indexer (Backend)
   - nasłuchuje: Smart Contract events
   - zapisuje do: Database
   - używa: BlockchainClient, Database

5. API (Backend)
   - udostępnia: REST endpoints
   - używa: Database, BlockchainClient
   - komunikuje się z: Mobile App

6. Mobile App (planowana)
   - komunikuje się z: API (odczyt), Blockchain (zapis transakcji)
   - zarządza: kluczami prywatnymi użytkownika

KLUCZOWE WYMAGANIA NIEFUNKCJONALNE

================================================================================
TECHNOLOGIE
================================================================================

Smart Contract:
- Język: Solidity 0.8.20
- Framework: Foundry (Forge, Cast, Anvil)
- Blockchain: Ethereum (lub kompatybilne L2)

Backend:
- Język: Rust
- Web framework: Axum 0.7
- Blockchain library: Alloy-rs 0.6
- Database: SurrealDB 2.0
- Async runtime: Tokio

Mobile App (planowana):
- Język: Swift
- UI Framework: SwiftUI
- Blockchain library: web3swift
- Storage: iOS Keychain
